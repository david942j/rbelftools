# Test Files

ELF files used by the specs. Everything here is generated by the [Makefile](./Makefile),
`make` regenerates all of them.

Regenerating a file changes the offsets and the build ID recorded in it, which specs
assert on. Only regenerate a file when a spec is going to be updated along with it.

## Sources

[source.cpp](./source.cpp) is linked against libc and is used for the executables.

[freestanding.cpp](./freestanding.cpp) includes no header and calls into no library, so
it can be compiled for any target without having that target's libc installed. It is
used for the object files.

|-|-|-|-|-|

| `amd64.nrelro.elf` | 64 | little | EXEC | X86-64 |
| `amd64.strip.elf` | 64 | little | EXEC | X86-64 |
| `i386.elf` | 32 | little | EXEC | Intel 80386 |
| `i386.pie.elf` | 32 | little | DYN | Intel 80386 |
| `i386.so.elf` | 32 | little | DYN | Intel 80386 |
| `aarch64.elf` | 64 | little | DYN | AArch64 |
| `arm.elf` | 32 | little | DYN | ARM |
| `arm.thumb.o` | 32 | little | REL | ARM |
| `riscv64.elf` | 64 | little | DYN | RISC-V |
| `ppc64.elf` | 64 | **big** | DYN | PowerPC64 |
| `mips.o` | 32 | **big** | REL | MIPS |
| `mips64.o` | 64 | **big** | REL | MIPS |

`libc.so.6` is not generated, it is a copy of the system library of some Ubuntu release.

Object files are ELF files as well, and they record the relocations a linker has yet to
resolve. Those relocations are far more diverse than the ones left in a linked file,
which is why some architectures are kept as objects:

- MIPS, because no MIPS libc is available to link against, see below.
- ARM Thumb, because Thumb only shows in relocations such as `R_ARM_THM_CALL`, which a
  linker resolves and does not record.

## Toolchain

x86 files are built by the host `g++`, which has to run on an x86 machine. All the other
files are built by `clang`, which compiles for every target it supports without needing a
per-target compiler, so they can be built anywhere.

Versions used to generate the current files:

| | |
|-|-|
| OS | Ubuntu 26.04 LTS |
| Compiler | Ubuntu clang version 21.1.8 (6ubuntu1) |
| Linker | Ubuntu LLD 21.1.8 |
| Linker (ppc64) | GNU ld (GNU Binutils for Ubuntu) 2.46 |

Install what the cross targets need:

```bash
sudo apt install -y clang lld \
  libstdc++-15-dev-arm64-cross \
  libstdc++-15-dev-armhf-cross \
  libstdc++-15-dev-riscv64-cross \
  libstdc++-15-dev-ppc64-cross \
  binutils-powerpc-linux-gnu
```

`clang` compiles for every target, but it links against the target's libc, so each target
still needs its libraries and headers. The `libstdc++-*-cross` packages bring those in,
no cross compiler is involved.

Two targets do not use `lld`:

- **ppc64** is linked by `powerpc-linux-gnu-ld`. Big endian PowerPC64 uses the ELFv1 ABI,
  which `lld` rejects with `ABI version 1 is not supported`. The 32-bit PowerPC binutils
  supports the `elf64ppc` emulation, so it links the 64-bit files too.
- **MIPS** is not linked at all. Ubuntu packages MIPS binutils but neither a MIPS compiler
  nor a MIPS libc, so there is nothing to link against. `freestanding.cpp` needs no libc
  and is compiled to an object file instead.
